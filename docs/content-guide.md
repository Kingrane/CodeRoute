# Как писать уроки

Задание — это не «напиши программу», а «собери программу из перемешанных строк».
Игрок видит 3–7 строк в случайном порядке и ставит их так, чтобы программа работала.
Поэтому все правила ниже — про то, чтобы у задания был **один** правильный порядок.

Формат полей — в `docs/content-schema.md`, там же пример. Здесь — как придумать задание,
чтобы оно не сломалось, когда его начнут проходить.

---

## Одно задание целиком

```json
{
  "id": "l01-t1",
  "prompt": "Собери программу, которая выводит «Привет, CodeRoute!»",
  "solution": [
    "message = \"Привет, CodeRoute!\"",
    "print(message)"
  ],
  "hint": "Сначала переменная получает значение, только потом её можно напечатать.",
  "explanation": "Python выполняет строки сверху вниз: print(message) сработает только после того, как message уже создана."
}
```

- `prompt` — что программа должна сделать. Одно предложение, без «пожалуйста» и «ваша задача».
- `solution` — правильный порядок строк. Пиши как обычную программу сверху вниз.
- `hint` — почему ответ неверный и куда смотреть.
- `explanation` — почему правильный ответ именно такой.

---

## Пять правил, без которых задание ломается

**1. Ровно один правильный порядок.**
Проверяй так: переставь две строки местами. Программа должна сломаться или выдать не то,
что написано в `prompt`. Если после перестановки результат тот же — строки надо переписать.

**2. Внутри задания нет двух одинаковых строк.**
Игрок не поймёт, какую из двух одинаковых строк куда ставить, а проверка сравнивает строки по порядку.

**3. Каждая строка — самостоятельная строка кода, без переносов.**
Если строка входит в тело `if` или `for`, отступ пишется внутри строки, пробелами:

```json
"solution": [
  "for number in range(3):",
  "    print(number)"
]
```

**4. Никакого `input()`.**
В браузере никто ничего не вводит. Все значения задавай прямо в коде: `age = 14`, а не `age = int(input())`.

**5. Программа запускается в Python 3 и делает то, что обещает `prompt`.**
Перед сдачей прогони все решения командой из `docs/content-schema.md`.

## `hint` и `explanation` — это разные вещи

| | Когда показывается | Что писать |
|---|---|---|
| `hint` | после ошибки | где именно ошибка и почему: «`print` стоит раньше, чем переменная получила значение» |
| `explanation` | после верного ответа | правило, которое закрепляем: «Python выполняет строки сверху вниз, поэтому...» |

Плохо: «Неверно, попробуй ещё раз», «Всё правильно, молодец».
Хорошо: «Сначала присвой значение, потом печатай — иначе имени ещё не существует».

По 1–2 предложения. Простым языком, без «таким образом» и «следует отметить».

---

## Чего избегать

- **Меньше 3 строк** — собирать нечего, задание решается угадыванием.
- **Две независимые строки**, которые можно переставить без последствий.
- **Очень длинные строки** — на телефоне не влезают в карточку. Держи до ~40 символов.
- **Темы из будущих уроков.** Урок 1 не должен требовать `if` или списков.
- **Подсказки-загадки.** `hint` объясняет причину, а не «подумай внимательнее».

## Проверка перед сдачей

1. Все программы урока выполняются:

```powershell
python -c "import json; d=json.load(open('content/python/lesson-01.json',encoding='utf-8')); [print('---',t['id'],'\n'+'\n'.join(t['solution'])) for t in d['tasks']]"
```

2. Прочитай `prompt` и собери программу по памяти: получается ровно один вариант?
3. Пройди урок в приложении руками — когда он появится на карте курса.
4. В каждом задании есть `hint` и `explanation`, и они написаны для школьника, а не для преподавателя.

## Темы по урокам

| Урок | Название | Тема |
|---|---|---|
| 1 | Первый вывод | `print`, переменные, строки |
| 2 | Числа и f-строки | арифметика, `int()`, вывод |
| 3 | Ветвления | `if`, `else`, сравнения |
| 4 | Циклы | `for`, `range` |
| 5 | Списки | `list`, `append`, `len` |

4 задания на урок. Название и описание урока в JSON должны совпадать с картой курса
(`src/mocks/lessons.json`), иначе на карте будет одно, а внутри другое.
