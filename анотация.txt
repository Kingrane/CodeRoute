Рабочее название: CodeRoute

Проблема и цель
Новички часто бросают изучение программирования: теория длинная, а готовые курсы не подстраиваются под их ошибки. Цель проекта — игровой сервис, где код учат короткими уроками-мини-играми по дереву уровней, а ИИ объясняет ошибки и помогает с заданиями на слабые места.

Описание проекта
CodeRoute — веб-сервис для изучения программирования. Курс состоит из уровней, каждый уровень — короткий урок из заданий в форме мини-игр: собрать программу из перемешанных строк, найти строку с ошибкой, угадать вывод кода. За правильные ответы начисляются очки, есть жизни. Если студент ошибся, сервис объясняет ошибку: сначала заготовленными подсказками, затем с помощью ИИ. На первом этапе курс по одному языку (Python), затем JavaScript, SQL и C#.

Целевая аудитория
Начинающие программисты: школьники старших классов и студенты первых курсов, которые хотят заниматься 5–10 минут в день. Дополнительно — преподаватели, которые могут рекомендовать сервис для практики сверх занятий.

Главные экраны

Вход в систему (на финале) и стартовый экран.
Карта курса: уровни и прогресс по ним.
Задание «Собери код»: перетаскивание перемешанных строк.
Задание «Найди баг»: выбор строки с ошибкой.
Задание «Угадай вывод»: выбор результата работы программы.
Итоги урока: очки, ошибки, разбор.
Профиль: очки, жизни, серия занятий.

Главные фишки и фичи

Короткие уроки-мини-игры вместо чтения длинной теории, обратная связь сразу после ответа.
Объяснение ошибок по конкретному ответу студента: сначала заготовленные подсказки, затем ИИ.
Игровая механика: очки, жизни, серия занятий.
Безопасный запуск кода: Python выполняется в браузере пользователя, а не на сервере.

Отличие от аналогов: сочетание мини-игр, разбора ошибок и заданий, подстроенных под слабые места конкретного пользователя, в одном сервисе для русскоязычных новичков. В известных нам аналогах такого сочетания мы не нашли.

Референсы
Duolingo (дерево уровней, жизни, серии, короткие уроки: берём механику), Stepik (русскоязычные курсы с автопроверкой: берём подход к проверке), LeetCode (задачи с тестами: берём модель проверки решений), Mimo и SoloLearn (мобильные уроки программирования). Отличаемся тем, что объясняем именно ошибки конкретного пользователя и подстраиваем задания под них.

Стек технологий
Фронтенд: React, Vite, Tailwind CSS, JavaScript. Бэкенд: C#, ASP.NET Core. База данных и вход: PostgreSQL (Supabase), на финале. ИИ: языковая модель через API (Groq) с резервным провайдером, на финале. Запуск Python в браузере: Pyodide или проверка без запуска кода. Инфраструктура: Docker, GitHub, Vercel или Render.

Риски проекта и их оценка

Ошибки в заданиях и объяснениях (вероятность средняя, влияние высокое). Снижаем: эталонный ответ и проверка каждого задания, ручная проверка выборки, кнопка «сообщить об ошибке».
Безопасность запуска кода (вероятность средняя, влияние высокое). Код выполняется только в браузере пользователя, на сервер не отправляется.
Лимиты бесплатного ИИ (вероятность средняя, влияние среднее). Снижаем: заготовленные подсказки как основа, кэш объяснений, ограничение запросов на пользователя, резервный провайдер.
Большой объём контента (вероятность высокая, влияние среднее). Снижаем: один язык на старте, шаблоны заданий, редактор заданий не делаем в первых версиях.
Разный уровень подготовки команды (вероятность высокая, влияние среднее). Задачи по уровню, регулярное ревью кода.
Пользователи бросят сервис (вероятность средняя, влияние среднее). Короткие уроки, тестирование на студентах до финала.
Ограничения бесплатного хостинга (вероятность средняя, влияние низкое). Пинг сервера через мониторинг, резервный хостинг фронтенда.

Что планируется к нулевой версии (предзащита)
Будет готово: один раздел Python (5–8 уроков), механика «собери код», проверка ответов, очки и жизни, прогресс в браузере пользователя, заготовленные подсказки к ошибкам, фронтенд и бэкенд, развёрнутые онлайн.

Планы на использование ИИ
В продукте. Языковая модель объясняет ошибку: получает условие задания, ответ студента и правильный ответ, возвращает короткое объяснение. Ответы кэшируются, в запрос не попадают имя, почта и логин. Для типовых ошибок есть заготовленные подсказки, ИИ подключается там, где они не помогли. Пример, где ИИ лучше фильтра: студент выбрал строку в задании «Найди баг», которая на самом деле верная. Фильтр ответит «неверно», а ИИ объяснит, почему строка корректна и в чём настоящая ошибка.

В разработке. ИИ-агенты пишут часть кода. Каждое изменение идёт через pull request с ревью другого участника, автор объясняет свой код. Автотесты покрывают проверку ответов, очки и жизни. Ручная проверка на тестовом деплое. Ключевую логику (проверку ответов, работу с ИИ) пишут и переписывают люди.
